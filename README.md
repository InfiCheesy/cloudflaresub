# CloudflareSub（Pages 版）使用说明

一个部署在 **Cloudflare Pages** 上的轻量「优选 IP 订阅器」：把你自建节点的链接（vmess / vless / trojan）粘贴进来，再填上 Cloudflare 优选 IP 或优选域名，它会把节点里的服务器地址批量替换成优选地址，生成一条**专属订阅链接**。把这条链接导入 V2rayN、Clash、Shadowrocket、Surge 等客户端，就能一键用上全部「换好优选 IP」的节点。

本项目基于 [InfiCheesy/cloudflaresub](https://github.com/InfiCheesy/cloudflaresub) 修改：原项目是 Cloudflare Workers 版本，本版本迁移到了 Cloudflare Pages，并陆续增加了明文输出、条目备注、有效期管理、KV 管理后台、动态订阅、优选地址混写等功能。感谢原作者。本项目以 [MIT 许可证](LICENSE) 发布。

**部署请看下面的「部署教程（小白向）」**——推荐从 Releases 下载现成的直传包，不需要自己从源码打包。**日常使用请看「使用教程（小白向）」**。功能细节都在「功能详解」里，遇到问题先翻「常见问题」。

## 功能详解

1. **Cloudflare Pages 一体化部署**
   - 从 Workers 迁移到 Pages 高级模式：静态页面与生成接口同仓同域，一次上传即可用；原版按 Workers 方式部署可能得到加不了 KV 绑定的「纯静态 Worker」（访问接口直接报 Error 1101），Pages 版不存在这个问题，万一绑定缺失接口也会返回可读的文字提示。
   - 全部功能跑在 Cloudflare 免费额度内，不需要绑信用卡：页面与接口用 Pages，数据存 KV，没有定时任务、没有常驻进程。

2. **节点输入：三种协议 + 整段订阅解析**
   - 支持 `vmess://`、`vless://`、`trojan://` 链接，一行一个；也可以直接粘贴一整段 base64 订阅内容，会自动解码出里面的节点。
   - 逐行容错：一批链接里个别行写坏了（无法解析、端口不可用）只跳过那一行并在结果里提示跳过了几行，不会整批失败。

3. **优选地址混写框**（v1.5.0 新增）
   - 第 2 步只有一个输入框，逐行混写、按填写顺序合并，不再有「手动填写 / API 动态来源」的模式切换（用法与 edgeTunnel 一类工具相同）：
     - **手写行**：IP、域名，可带 `:端口` 和 `#备注`（写法见使用教程的速查表），生成后固定不变；
     - **来源链接行**：一行一个 `https://` 链接，生成时会拉取该链接的优选列表并展开合并进来。
   - 来源链接最多 **5 个**、并行拉取；「每个链接最多取前几个」（1–100，默认 10）逐个控制每个来源用多少；同一个地址被手写行或多个来源重复给出时，只保留先出现的一个。
   - 框里含 http 链接、链接超过 5 个等明确写错的情况会直接报错说明，不会静默吞掉；某个来源拉取失败时，只要还有其他地址可用就照常生成，并在结果里点名提示是哪个来源失败（该来源仍保留在订阅里，恢复后自动生效）。

4. **动态订阅：订阅自动跟随最新优选 IP**（v1.3.0 引入，v1.5.0 改为混写）
   - 优选框里**只要含来源链接，生成的就是动态订阅**：手写行固定，链接部分约每小时跟随来源的最新列表，客户端不用换链接、你也不用重新生成。
   - 跟随是「懒刷新」：Pages 没有定时任务，刷新发生在有人拉取订阅、且缓存已过期的时候。缓存规则：每个来源在 KV 里有一份共享缓存，新鲜期 1 小时；刷新失败时 5 分钟内不重复尝试；来源不可用时依次用 KV 缓存、该来源在条目里存的快照兜底，订阅不会中断。
   - 来源列表格式：一行一个 IP / 域名（可带 `:端口`），也支持 CSV 测速结果（取每行第一列）和 JSON 列表。
   - 拉取安全：只允许 `https://`；拒绝指向内网的地址（只按 IP 本身判断，不误伤 `fcdn`、`10.` 开头的正常域名）；重定向的落点会重新校验；5 秒超时、响应最多读 512 KB；链接里写的账号密码会被剥掉、不存入条目；链接末尾的 `#备注` 会被忽略，不会把同一份列表拆成多个条目。

5. **六种输出格式，覆盖主流客户端**
   - 结果区和每条订阅都有六张链接卡片：**自动识别**（按客户端的 User-Agent 返回合适格式，通用首选）、**V2rayN**（base64）、**Clash**（YAML 配置）、**Surge**（Profile）、**Shadowrocket**、**明文链接**（一行一条节点链接、每个优选地址一条，肉眼可读、可整段复制）。
   - 订阅链接形如 `https://你的域名/sub/<id>?token=<链接令牌>`，也可以自己拼参数指定格式：`&target=raw`（base64）、`&target=clash`、`&target=surge`、`&target=plain`（明文），不写 target 即自动识别。

6. **短链 + 内容去重**
   - 生成结果存入 Cloudflare KV，只对外给一条 `/sub/<id>` 短链接。
   - 同一批节点 + 同一批优选内容 + 同一名称前缀，重复生成得到的是**同一条链接**（刷新原条目，有效期以最后一次生成的选择为准、重新计时）。动态条目的「同一批」按手写行 + 来源集合 + 取前 N 判定，不按来源当天的 IP 判定，所以来源轮换不会产生新条目。
   - 特例：只有一个来源链接、没有手写行的订阅，与旧版本「API 动态来源」填法算出的是同一个条目，升级后重新生成不会重复。

7. **双令牌安全：链接令牌 ≠ 管理令牌**
   - 每条订阅链接里带的是**该条目专属的链接令牌**：由管理令牌在服务器内部签名算出（HMAC），只能打开它自己这一条订阅，进不了管理区、也打不开别人的订阅；管理令牌永远不会出现在任何链接里。
   - 管理令牌 `SUB_ACCESS_TOKEN` 只用于生成和管理（请求头或请求体内传递，页面上填一次浏览器会记住）。生成也要令牌，是为了防止陌生人打开你的站点乱生成、耗光 KV 写入额度。
   - ⚠️ 更换管理令牌后，**所有已发出的订阅链接随之失效**，需重新生成再分享。早期版本（v1.1.0 及更早）曾把管理令牌原文拼在订阅链接里，从那种版本升级的人请务必更换一次令牌。

8. **条目备注**
   - 生成时可随手给条目写备注（如 `us-vps-1`，标明是哪台 VPS、什么用途），管理区也能随时修改；备注最长 80 字。
   - 管理区改备注是**自动保存**（没有保存按钮）：停笔约 1 秒、或点到别处，就自动存入，并**回读 KV 里这条记录本身验证**——确认写入成功，备注框下方才短暂显示「备注保存成功」；服务器已存入但回读一时读不到新值时，显示黄色「备注已保存，待刷新确认」而不是误报失败；真的失败才红字提示。改有效期的保存同样有回读验证（按钮显示「成功 / 失败」）。列表与详情也一律直读记录本体，不看 KV 的列表索引（它有同步延迟，曾导致改完显示旧值）。

9. **有效期管理**
   - 生成时可选：**永久保存**（默认）或**自定义天数**（1–3650 天），到期后 KV 自动删除这条订阅、链接随之失效；选永久时天数框自动置灰隐藏。
   - 已生成的条目在管理区点「修改有效期」就行内改期限（改永久、或从现在起重新计时 N 天），同样带回读验证。删除条目会连同它的备注指针、去重指针一并清理，删完零残留、不会「删了又被重新生成找回来」。

10. **KV 条目管理后台**
    - 页面底部自带，令牌保护。加载后每条订阅一行：备注、创建时间、有效期、来源 VPS / 节点、生成节点数；动态条目标有「动态订阅」徽章（多来源的会写明「N 个来源跟随更新」）。
    - 点「链接 / 收起」展开条目，里面就是与结果区**同款的六张链接卡片**（复制 / 二维码），不需要另记复制入口。

11. **管理工具：排序、搜索、批量删除**
    - **六种排序**：创建时间、名称、剩余有效期，各正序 / 倒序（永久按无限大算）。
    - **搜索**：工具栏搜索框按备注、标签或来源 VPS / 节点实时过滤（不区分大小写），计数行会显示「共 X 条，符合 Y 条」。
    - **批量删除**：每行行首有复选框，表头是三态全选框（只全选当前显示的条目）；工具栏「删除所选（N）」逐条删除并在按钮上显示进度，失败的条目会保留并点名。切换搜索 / 排序 / 重新加载会清空勾选。
    - **展开全部 / 收起全部**：同时控制链接卡片、「修改有效期」面板和「标签」面板；展开某条往下翻时，这一行会吸在页面顶部方便随时收起。

12. **一键回填修改**
    - 任意条目点「回填到生成区」，它当初的输入会回到上方表单，改完重新生成即可：**内容没变刷新原条目**（有效期重新计时），**改了内容生成新条目、新链接**。
    - 新条目存有原始输入（节点原文上限 100,000 字、优选框原文上限 50,000 字），回填逐字精准；更早的老条目没有存原文，会由已存的节点数据还原（界面会注明，可能与原始输入略有差异）。
    - 混写条目回填的是整个混写框原文；旧版单链接动态条目回填后，框里是它的来源链接一行（它当时的快照 IP 在该条目展开的链接卡片里仍能看到）。

13. **结果预览：全部节点一览**
    - 生成结果的预览列出**全部**生成节点（不再只显示前 20 条），放在固定高度的框里滚动查看、表头吸顶；每行显示节点名、类型、地址、端口等。

14. **版本显示与更新提示**
    - 页面标题旁有版本徽章，显示当前运行版本。服务端每 6 小时向 GitHub 查一次最新 Release（结果缓存在 KV，查不到时 30 分钟内不重复打扰 GitHub）：
      - 有新版：徽章变成直达 Release 页的链接，写明新旧版本号；
      - 检查失败：徽章标红「检查失败」，标题下方出现整幅黄色警告，可点「重新检查」（手动重试真实检查最快每 5 分钟一次）；
      - 显示的是上次成功结果时：标明「上次结果」，同样有警告条，不会拿旧结果冒充最新。

15. **右下角快速定位**（v1.4.2 新增）
    - 回顶按钮上方常驻三个液态玻璃按钮「生成 / 结果 / 管理」，页面一打开就能点，一键平滑跳到对应区块（进门直奔管理区不用滚半天）；正在浏览的区块会自动高亮（按视口 40% 高度线判定）。
    - 回顶按钮仍是滚动后才出现，它的位置在列里预留好了，整列按钮不会跳位。

16. **触摸与手机优化**
    - 全站按触屏规范：主要点击目标 ≥48px、表单字号 16px（防 iOS 聚焦自动缩放）、备注框与下方标签区各占行高的一半、框内可滚动（拖动与滚轮都可），手机上好点、好滑、好读。

17. **输出安全与规模上限（历轮自查成果）**
    - 节点链接里的字段（密码、路径、主机名等）写入 Clash / Surge 配置前都经过引号转义与换行清洗，恶意链接至多生成它自己那条节点，不能污染配置、伪造条目。
    - 生成规模有明确上限：节点数 × 优选地址数超过 **10,000** 会直接提示组合过多及具体数字，不会撞上 KV 单条容量后只报一句看不懂的服务器错误。
    - 不存在的接口路径返回规范的 JSON 404；管理区渲染前对有效期天数强制做数字校验。

18. **数据都存在哪（KV 键一览）**
    - `sub:<id>` 条目记录本体（节点、备注、有效期、动态配置都在里面，列表与验证都以它为准）；
    - `dedup:<哈希>` 内容去重指针；`note:<备注>:<id>` 备注指针（与条目同期限，删除时一并清理）；
    - `ipcache:<来源哈希>` 每个来源一份共享缓存（多个条目用同一来源只拉一次；删条目不会删它）；
    - `sys:latest-release` 版本检查缓存。没有其他外部存储，不上传任何数据到第三方。

19. **条目标签**
    - 每条订阅可打**多个标签**（如「香港」「主力」）：生成时在表单的标签选择器里点选已有标签或输入新建（回车添加），管理区点行内「标签」按钮也能随时增删。每条最多 10 个、单个最长 24 字（自动去空格、去重）；保存后同样**回读 KV 验证**才报成功。两处可编辑的标签都支持**长按拖动排序**（按住约 0.2 秒拾起再拖，顺序即保存的顺序）。
    - 标签只存在条目记录里（和备注一样、随条目一起过期与删除，无额外索引键），**不参与内容去重**：重新生成命中已有条目时，没动过生成表单的标签选择就不会改动它的标签，在选择器里改了（包括清空）才整体替换；回填会把标签一并带回生成表单。
    - **按标签筛选**：管理区有标签筛选条，全部标签带计数列出、可多选，模式可在「包含全部（同时拥有全部所选标签）/ 包含任一」之间切换（默认包含全部）；点条目行上的标签徽章也能一键把它加入筛选。筛选与搜索框叠加生效，搜索文本本身也能命中标签。筛选条上的标签同样能**长按拖动排序**（顺序保存在服务端，所有设备打开都是同一套排列；旧版本记在浏览器本地的顺序会在首次打开管理区时自动导入服务端一次；页面切回前台时自动刷新顺序，不会拿旧排列覆盖其他设备的修改）；长按时左侧「标签筛选」会变成垃圾桶，把标签拖到上面松手，就能把这个标签从**全部条目**上删除（会先弹确认）。

20. **诊断日志导出（脱敏）**
    - 页面最下方有「导出诊断日志（已脱敏）」按钮，点一下下载一份文本日志，用来排查「订阅突然失效、某个来源总拉不到、页面报错」这类疑难问题。内容包括：浏览器环境与网络类型、应用版本与更新检查状态、导出当场实测的接口耗时与**本机/服务器时钟偏差**、本次会话的全部操作流水（哪个接口、成败、耗时）、页面报错记录、条目聚合统计（总数、动态/静态、记录体积、条目年龄、来源缓存新鲜度），以及服务端最近 60 条事件（接口成败与耗时、来源抓取失败记录，含失败类别与耗时）。
    - **脱敏是白名单式的**：日志只采集计数、状态、耗时这类预定义字段，管理令牌、节点链接、优选 IP、备注与标签内容从源头就不进日志；来源主机名只以密钥哈希形式出现（能看出「是不是同一个来源在反复失败」，反推不出域名）；导出前还有一道正则清洗兜底。可以放心把日志文件发给维护者或贴到 Issue 里。

## 部署教程（小白向）

只需要一个 Cloudflare 账号（**免费即可，不用绑信用卡**）。三种部署方式选一种：**方式 A 控制台直传**最简单、适合第一次部署；**方式 B 连接 GitHub** 适合想长期维护代码的人；**方式 C 命令行（Wrangler）** 适合直传总是失败、或想反复快速更新的人。

无论哪种方式，部署完都要给项目加两样东西，缺一不可：

1. **KV 命名空间绑定**（变量名必须叫 `SUB_STORE`）：保存订阅数据的「仓库」；
2. **环境变量 `SUB_ACCESS_TOKEN`**：管理令牌，相当于这个站的管理密码，自己定一个长一点的字符串并记牢。

加完绑定和变量后**必须重新部署一次**才生效（每个方式的末尾都写了这一步，别漏）。

### 方式 A：控制台直传（推荐新手）

1. 登录 [Cloudflare 控制台](https://dash.cloudflare.com/)，左侧点 **Workers 和 Pages**（Workers & Pages）。
2. 点 **创建（Create）** → 选 **Pages** 标签页 → **上传资产（Upload assets）**。
   - ⚠️ 一定要走 Pages 这条路。走错到 Workers 上传通道会得到一个「纯静态 Worker」，加不了下面的绑定，页面还会报错。
3. 给项目起个名字（比如 `my-sub`），点创建。
4. 把从 Releases 下载的 `cloudflaresub-pages-upload.zip` **整个拖进**上传框（不用解压，Pages 会自动解压；先解压再把里面文件全选拖进去也可以），点 **部署（Deploy）**。
5. 部署完成后，进入该项目 → **设置（Settings）→ 绑定（Bindings）→ 添加（Add）**：选 **KV 命名空间**，变量名填 `SUB_STORE`（一字不差），命名空间没有就新建一个再选它。
6. 同样在 **设置 → 变量和机密（Variables and secrets）→ 添加**：变量名填 `SUB_ACCESS_TOKEN`，值填你自定的令牌（建议选「机密 / Secret」类型）。
7. ⚠️ **关键一步**：回到项目的 **部署（Deployments）** 页，点 **创建新部署（Create a new deployment）**，把同一个 zip 再拖进去部署一次，让绑定和变量生效。
8. 打开项目给的 `https://你的项目名.pages.dev`，能看到页面就是部署成功了。接着做下方「部署后检查清单」。

### 方式 B：连接 GitHub 仓库

1. 先把本仓库弄到你自己的 GitHub 名下（Fork 本仓库即可）。
2. Cloudflare 控制台 → **Workers 和 Pages → 创建 → Pages → 连接到 Git（Connect to Git）**，选中你的仓库。
3. 构建设置：框架预设选 **无（None）**，构建命令留空，构建输出目录填 `public`，点部署。
4. 按方式 A 的第 5–6 步添加 KV 绑定 `SUB_STORE` 和变量 `SUB_ACCESS_TOKEN`，然后在部署页**重新部署一次**让它们生效。
5. 以后每次往 GitHub 仓库推送新代码，Cloudflare 会自动重新部署，不用再手动上传。

### 方式 C：命令行部署（Wrangler）

适合直传在你的网络环境下总是卡住、失败，或想以后一条命令快速更新的人。需要先装好 [Node.js](https://nodejs.org/)（LTS 版即可）。

1. 把 `cloudflaresub-pages-upload.zip` 解压到一个固定文件夹（比如 `D:\my-sub-site`），以后每次更新都是：下载新包 → 解压覆盖这个文件夹 → 跑第 4 步的命令。
2. 如果项目还没建过，先按方式 A 在控制台建好 Pages 项目（名字记下），并完成绑定 `SUB_STORE` 与变量 `SUB_ACCESS_TOKEN` 的添加。
3. 在该文件夹里打开终端，第一次先登录（会弹出浏览器授权，点同意即可，只需一次）：
   `npx wrangler login`
4. 部署（一行命令）：
   `npx wrangler pages deploy . --project-name 你的项目名 --branch main`
   - Windows 的 PowerShell 若提示脚本被禁止运行，把 `npx` 换成 `npx.cmd`：`npx.cmd wrangler pages deploy . --project-name 你的项目名 --branch main`（不要去改系统的执行策略）。
   - 输出里 `Uploaded N files` 是本次真正更新的文件数；显示 `0 files` 说明文件夹里的文件和线上完全相同——多半是新包没有解压覆盖到位，先检查文件夹里 `_worker.js` 的 `APP_VERSION` 再重试。
5. 命令给出 `https://xxxx.你的项目名.pages.dev` 的部署地址，打开主域名确认版本徽章已是新版本号。

### 部署后检查清单

- [ ] 打开站点首页，标题旁能看到版本徽章（如 `v1.6.0`）；
- [ ] 拉到页面底部「KV 条目管理」，填入 `SUB_ACCESS_TOKEN`，点「加载条目列表」不报令牌错误（空列表是正常的）；
- [ ] 回到上方随便粘一个节点 + 一个优选地址，点「生成订阅」，结果区能出链接；
- [ ] 点开结果区的「明文链接」卡片，能打开并看到节点链接——至此部署完成。

## 使用教程（小白向）

### 第一次使用：先填管理令牌

生成和管理共用同一个令牌。第一次打开站点，先拉到页面下方「KV 条目管理」处，把部署时设的 `SUB_ACCESS_TOKEN` 填进令牌框（浏览器会记住，之后自动带上），再回上方生成。没填令牌点生成会提示需要管理令牌，这是故意的：生成要往 KV 写数据，不能让陌生人打开你的站点随便写。

### 生成订阅（四步）

1. **粘贴节点链接**：自建节点的 vmess / vless / trojan 链接，一行一个；或整段 base64 订阅内容直接粘。
2. **填优选地址（混写框）**：一行一个，手写行与来源链接行可混写，写法见下方速查表。
3. **可选设置**：
   - **名称前缀**：给这一批节点统一加前缀，方便在客户端里认；
   - **保留原始域名和端口**：勾上后优选地址只替换 IP 部分（少见需求，一般不勾）；
   - **条目备注**：写这条订阅是哪台 VPS、什么用途，如 `us-vps-1`，以后在管理区靠它认条目；
   - **条目标签**：点选已有标签或输入新标签回车添加（如「香港」「主力」），方便日后在管理区按标签筛选；重新生成已有条目时没动过这里，就不会改动它的标签；
   - **存储期限**：永久保存（默认），或自定义天数（到期自动删除）。
4. 点 **生成订阅**，下方「结果」区会出现六张链接卡片和全部节点预览。

### 优选框写法速查

**手写行**（一行一个，生成后固定不变）：

| 写法 | 例子 | 说明 |
|---|---|---|
| IPv4 | `104.16.0.1` | 不带端口时用节点自己的端口 |
| IPv4 + 端口 | `104.16.0.1:8443` | |
| 域名 | `cdn.example.com` | 优选域名同理，可带 `:端口` |
| IPv6 裸地址 | `2606:4700:4700::1111` | 直接填，不用方括号 |
| IPv6 + 端口 | `[2606:4700:4700::1111]:443` | 带端口必须加方括号 |
| 备注 | 在任意手写行末尾加 `#备注` | 如 `104.16.0.1#HK-01`，会体现在节点名里 |

**来源链接行**（一行一个 `https://` 链接）：

- 最多 5 个；拉取内容一行一个地址（可带 `:端口`），CSV 取第一列，JSON 列表也可；
- 「每个链接最多取前几个」控制每个来源用多少（默认 10）；
- 链接后写 `#备注` 会被忽略（不会算进地址）；`http://` 的链接不收，会直接报错；
- 点优选框下方的 **「测试拉取链接」**，会把框里所有链接逐个实测一遍：每个链接拉到几个地址、哪个失败、为什么失败，一行一个结果，先测再生成更稳妥。

**混写示例**（手写 2 个固定地址 + 2 个动态来源）：

```text
104.16.0.1#固定-香港
cdn.example.com:443#固定-域名
https://example.com/ips.txt
https://example.org/cf-list.txt
```

这样生成的订阅里，前两行永远不变，后两个来源的地址约每小时跟随更新。

### 动态订阅的使用要点

- 含来源链接即动态，不用另开开关；纯手写（一个链接都没有）就是普通静态订阅。
- 跟随节奏约一小时：来源换了 IP 后，最迟约一小时（且期间有人拉取过订阅）就会跟上；没人拉取时不刷新，这是 Pages 无定时任务的懒刷新机制，属正常现象。
- 来源临时挂了不用管：缓存和快照会顶着，订阅不断；来源恢复后自动跟上。只有「生成那一刻所有来源都拉不到、又没有任何手写地址」才会生成失败并说明原因。

### 把订阅导入客户端

结果区（和管理区展开条目里）的六张卡片，每张都有**复制**和**二维码**按钮：

| 格式 | 用在哪 |
|---|---|
| 自动识别 | 通用首选，服务器按客户端类型自动返回合适格式 |
| V2rayN | V2rayN / v2rayNG |
| Clash | Clash / Mihomo / Clash Verge |
| Shadowrocket | iPhone / iPad 小火箭 |
| Surge | Surge 的 Profile 导入 |
| 明文链接 | 不是订阅格式，是逐行的明文节点链接：可整段复制走，也可打开肉眼检查内容 |

导入方法都一样：在客户端里找「订阅」→「添加订阅」，粘贴链接保存，再点一次「更新订阅」；手机上也可以直接扫卡片上的二维码。

### 管理已生成的条目（页面底部「KV 条目管理」）

1. 令牌框填 `SUB_ACCESS_TOKEN`，点 **加载条目列表**。
2. 每条一行：备注、创建时间、有效期、来源 VPS / 节点、节点数先看个大概；动态条目有徽章。
3. 每行的操作：
   - **链接 / 收起**：展开这条的六张链接卡片（和结果区同款），复制各格式链接或看明文都在里面；
   - **备注（自动保存）**：直接在备注框里改，停笔约 1 秒或点到别处就自动保存；回读 KV 确认后，框下方会短暂显示绿字「备注保存成功」，失败则显示红字提示；
   - **标签**：展开行内编辑面板给这条增删标签（点选已有或输入新建），保存同样有回读确认；备注下方的标签徽章点一下即按该标签筛选，管理区上方的标签筛选条可多选多个标签（「包含全部 / 包含任一」可切换）；
   - **修改有效期**：展开行内面板，改永久或从现在起重新计时 N 天，保存同样有回读确认；
   - **删除**：删掉这条订阅，链接立即失效（会先弹确认框）；记录、备注指针、去重指针一并清干净；
   - **回填到生成区**：把这条当初的输入填回上方表单（见功能详解第 12 项），改完再点生成即可。
4. 列表上方：**排序**下拉（六种）、**搜索框**（按备注或来源过滤）、**展开全部 / 收起全部**、**删除所选（N）**（先勾行首复选框；全选只选当前显示的，删除逐条进行并显示进度，失败保留并点名）。
5. 小贴士：展开某条往下翻时这行会吸顶；页面右下角圆形按钮回顶部，它上方「生成 / 结果 / 管理」三个玻璃按钮可一键跳区块；标题旁的版本徽章显示当前版本，有新版时会变成下载链接、检查异常时会给出黄色警告，都可点「重新检查」。

### 订阅链接的规律（进阶）

- 同内容重复生成 = 同一条链接（规则见功能详解第 6 项）；想「换一条新链接」，改名称前缀或增减一个地址即可生成新条目。
- 条目的有效期以**最后一次生成 / 修改**时选的为准并重新计时；纯客户端拉取订阅不会续期。
- 自己拼链接时记得带上 `token` 参数：没有它或 token 不对，订阅会返回 403。token 是这条订阅专属的，和管理令牌不是一回事（见功能详解第 7 项）。

## 常见问题

**打开网站报 1101 错误？**
多半是部署通道选错（部署到了 Workers 而不是 Pages），或文件不是最新版。按「方式 A」在 Pages 通道重新部署一次最新文件一般即可。

**设置里加不了绑定 / 绑定按钮是灰的？**
说明这个项目是「纯静态 Worker」，不是 Pages 项目，天生没有脚本、加不了绑定。到 Workers 和 Pages 里新建一个 **Pages** 项目重来。

**部署成功但版本号没变 / 功能没更新？**
多半是新包没真正覆盖进部署目录：所有版本的包同名，下载夹里容易混。先解压新包，用记事本打开 `_worker.js` 搜 `APP_VERSION` 确认是新版本号，再部署；命令行部署时若显示 `Uploaded 0 files`，也是文件夹内容没换的信号。

**管理区点加载提示令牌不正确（403）？**
检查三件事：令牌是不是和 `SUB_ACCESS_TOKEN` 一模一样（大小写、多余空格）；加完变量后有没有**重新部署**；粘贴时有没有带空格。

**点「生成订阅」提示需要管理令牌？**
生成要往 KV 写数据，同样需要令牌。在页面下方「KV 条目管理」的令牌框里填入 `SUB_ACCESS_TOKEN` 即可（填过一次浏览器会记住），再回来点生成。

**刚改完备注 / 期限，列表里偶尔还是旧的？**
Cloudflare KV 是「最终一致」存储，跨地区同步偶尔要几秒。本站的确认和列表都直读记录本身，正常情况下点一次加载就会对上；若真遇到，隔几秒再加载一次即可。

**条目不见了 / 订阅打开 404？**
要么被手动删除了，要么有效期到期被 KV 自动清除了。重新生成一次即可（相同内容会得到同一条链接）。

**订阅打开 403？**
链接里的 `token` 缺失或不对：用结果区 / 管理区卡片里给出的完整链接，不要自己截断；若刚更换过管理令牌，旧链接全部失效，重新生成再分享。

**动态订阅怎么没跟随来源更新？**
依次排查：来源本身真的换了 IP 吗；距离上次有人拉取订阅是否已超过约一小时（懒刷新，没人拉取不刷新）；来源是否拉取失败（重新生成一次，看结果里有没有点名某个来源失败）；客户端是否缓存了旧订阅（在客户端手动点一次更新订阅）。

**来源拉取失败有哪些原因？**
链接不是 https、指向内网地址、来源站超时或返回超过 512 KB、内容里没有可用的 IP / 域名，都会失败。先用优选框下方的「测试拉取链接」逐个测，报错信息会写明原因。

**优选 IP 填了 IPv6 节点却坏了？**
IPv6 裸地址直接一行一个填就行；带端口必须写成 `[地址]:端口` 的方括号形式。

**令牌忘了怎么办？**
去 Pages 项目设置里看 `SUB_ACCESS_TOKEN`；机密类型看不到明文的话，就直接改一个新的，然后重新部署，再用新令牌（注意：换令牌会让已发出的订阅链接全部失效，需重新生成分享）。

**把订阅链接发给别人，他能用链接里的 token 进我的管理后台吗？**
不能。链接里的 token 是这条订阅专属的签名令牌，只能打开这一条订阅，进不了管理区、也打不开别人的订阅；管理令牌永远不会出现在任何链接里。

## 安全提醒

- `SUB_ACCESS_TOKEN` 相当于管理密码：别写进代码、别提交到公开仓库、别发给别人；它只应该出现在 Cloudflare 项目设置里。
- 订阅链接谁拿到谁就能用（链接令牌只能开这一条，但能用这一条的全部节点），请勿公开分享。
- 动态来源请用你信任的列表地址：来源里的地址会被直接写进你的订阅节点。
- 使用本工具请遵守当地法律法规和服务商条款。

## 本地开发

需要 Node.js 18+。

```bash
# 本地把站点跑起来（在仓库根目录）
npx wrangler pages dev public

# 跑测试（冒烟 + 接口全量用例）
npm run check
```

目录结构：

```text
cloudflaresub/
├─ public/           # 部署到 Pages 的全部运行文件（构建输出目录）
│  ├─ index.html     # 页面
│  ├─ app.js         # 前端逻辑
│  ├─ styles.css     # 样式
│  ├─ _worker.js     # Pages 入口（与 src/worker.js 保持内容一致）
│  └─ icons/         # 客户端图标
├─ src/
│  ├─ worker.js      # 服务端源码（改代码改这里，再同步到 public/_worker.js）
│  └─ core.js        # 解析 / 渲染核心函数（测试使用）
├─ tests/            # 自动化测试
├─ wrangler.toml     # Pages 项目配置
└─ package.json
```
